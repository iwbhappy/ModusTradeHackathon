# Сигнал · Модус Трейд

Кликабельный UI-прототип системы внутренних обращений. Этап 1 по [ТЗ](docs/specs/01-ui-prototype.md): React 18, TypeScript strict, Vite, Tailwind, React Router, zustand. Бэкенда, внешних API и LLM нет. Данные вымышленные.

## Запуск

Нужен Node.js 22 LTS и npm.

```sh
cd frontend
npm install
npm run dev
```

Откройте адрес, напечатанный Vite, обычно `http://localhost:5173`. Шрифты установлены локально через Fontsource; CDN не нужен. При первой установке npm потребуется интернет. Кэш npm направлен в `frontend/.npm-cache` для работы в ограниченной файловой среде.

```sh
npm run build
npx tsc --noEmit
npm run preview
```

Сборка находится в `frontend/dist`. При размещении на статическом сервере настройте возврат `index.html` для неизвестных маршрутов React Router.

В ограниченной среде Windows процессы esbuild при запуске dev-сервера могут блокироваться с `spawn EPERM`. Это ограничение среды выполнения; в текущей сессии production-сборка прошла, preview с `npm run preview -- --configLoader native` отдавал HTTP 200. Проверка сценариев в браузере в этой среде не выполнена. Подробности — в [отчёте этапа](docs/reports/01-ui-prototype.md).

## Как устроено демо

Верхняя панель позволяет выбрать роль и конкретного пользователя. Это демонстрационный переключатель, а не авторизация. Роль сотрудника открывает свои и присоединённые обращения; руководитель видит назначения себе и своему подразделению; администратор — настройки. Руководителям доступна сводная аналитика всей компании. В её детализации кнопка «Открыть как ответственный» явно переключает демонстрационного пользователя.

Обращения, комментарии, присоединения, решения, правила и отпуска сохраняются в localStorage одного браузера и одного origin. Обновление страницы сохраняет их. Другая вкладка получит изменения после перезагрузки. Кнопка «Сбросить демо-данные» внизу сайдбара восстанавливает 60 обращений и начальные правила. Перед показом используйте сброс.

## Демо по шагам

### 1. Похожие обращения и новая проблема

1. Выберите **Сотрудник → Сотрудник закупок**, откройте «Новое обращение».
2. Введите: «В рабочих материалах разные обозначения одного изделия увеличивают время проверки спецификации. Нужна актуальная карточка позиции». После небольшой паузы справа появятся похожие обращения.
3. У обращения, к которому вы ещё не присоединились, нажмите «У меня то же самое → присоединиться», заполните контекст минимум из 10 символов и подтвердите. Откроется карточка; обращение появится в «Мои обращения», а оценка потерь увеличится.
4. Отдельно откройте новую форму. Выберите «Проблема», категорию **Межотдельное взаимодействие**, подразделение **Закупки**. Введите: «В заявках на оборудование не указаны условия эксплуатации. Предлагаю добавить обязательные параметры и срок поставки».
5. Нажмите «Структурировать текст». Рассмотрите предложенные проблему, решение, эффект, категорию и приоритет; нажмите «Принять» или «Отклонить». Принятые поля можно редактировать.
6. Укажите частоту и потерю времени, выберите файл-заглушку. У файла сохраняется только имя. Внизу формы видны ответственный и сроки. Отправьте обращение, запомните ID `N-001`.

### 2. Уточнение → реализация → подтверждение

1. Выберите **Руководитель → Руководитель закупок**. Во «Входящих» откройте созданное обращение.
2. В панели действий оставьте «В работе», нажмите «Сохранить решение».
3. Выберите «Ожидает уточнения». Введите вопрос минимум из 10 символов или получите «Черновик ответа», примите его и отредактируйте. Сохраните.
4. Переключитесь на **Сотрудник → Сотрудник закупок**. Обращение будет в блоке «Требуют вашего действия». Откройте его и ответьте в обсуждении. Статус вернётся на рассмотрение.
5. Снова выберите руководителя закупок, откройте обращение и статус «Реализовано». Заполните «Что изменилось», например: «В шаблон заявки добавлены обязательные поля назначения, параметров и срока поставки. Памятка опубликована для сотрудников». Сохраните.
6. Автор видит результат и кнопки «Проблема решена» / «Не решена — вернуть». Для показа возврата выберите вторую кнопку и укажите причину; руководитель увидит «Возвращено автором» и сможет повторно взять в работу и реализовать. Срок возвращённого обращения обновляется.
7. Нажмите «Проблема решена»: статус станет «Закрыто», появится подтверждение автора. В «Сделано» есть карточка «было → стало»; в аналитике обновится число подтверждённых решений.
8. Перезагрузите страницу и убедитесь, что статус, результат и история сохранены.

### 3. Мотивированный отказ

1. Выберите **Сотрудник → Сотрудник офиса**. В его списке уже есть `A-017` с исходной мотивировкой отказа.
2. Для нового отказа создайте предложение в категории **Корпоративная среда**, подразделение **Администрация**: «Предлагаю оборудовать дополнительное помещение для коротких перерывов рядом с рабочей зоной».
3. Выберите **Руководитель → Административный руководитель**, откройте новое обращение, выберите «Отклонено» и шаблон о неподходящем помещении. При необходимости исправьте текст и сохраните. Пустую мотивировку сохранить нельзя.
4. Вернитесь к **Сотруднику офиса**: автор видит причину отказа и историю.

### 4. Основной ответственный в отпуске

1. Выберите **Администратор**, откройте «Пользователи и роли». У **Руководителя закупок** включите «В отпуске».
2. В «Маршрутизации» посмотрите основного и резервного для категории «Межотдельное взаимодействие». Можно отредактировать правило и сроки в модальном окне.
3. Выберите **Сотрудник → Сотрудник закупок**, создайте проблему этой категории. Перед отправкой форма покажет резервного и причину замены. По исходным правилам это **Ответственный за процессы**.
4. Отправьте обращение, выберите роль руководителя и пользователя, указанного в форме. Обращение будет в его входящих. Если оба ответственных в отпуске, отправка блокируется с объяснением: администратору нужно исправить правило.

### 5. Аналитика и просрочки

1. Выберите **Руководитель → Руководитель закупок**. Во «Входящих» нажмите «Просрочены», попробуйте фильтры категории, подразделения, приоритета и срока, затем сортировку «По стоимости проблемы».
2. Откройте «Аналитика». Переключите 30 / 90 дней / всё время. Посмотрите показатели первого ответа, реализации и подтверждения авторами, распределения и динамику.
3. В «Повторяющихся проблемах» нажмите название кластера: откроется список и суммарные потери времени.
4. Нажмите непустую ячейку матрицы трения: откроется список проблем для выбранной пары подразделений. Кнопка «Открыть как ответственный» переводит в карточку от имени её ответственного.
5. Вернитесь в аналитику и нажмите подразделение в «Контроле SLA»: откроются его просроченные обращения. Во всех списках работает поиск по ID и тексту.

## Структура

- `frontend/src/types.ts` — контракты данных.
- `frontend/src/data/seed.ts` — построение 60 демо-обращений, пользователей, справочников, правил и шести кластеров.
- `frontend/src/data/originals.json` — точные поля исходных A-001…A-020, извлечённые из датасета.
- `frontend/src/api/index.ts` — единственный слой чтения и изменения предметных данных; асинхронные функции с задержкой 160 мс.
- `frontend/src/store.ts` — сессия демонстрационного пользователя и обновление интерфейса через zustand.
- `frontend/src/pages/` — экраны; `components/` — общие элементы; `styles.css` и `tailwind.config.js` — оформление и токены.

На следующем этапе API-слой можно заменить HTTP-вызовами, сохранив контракты экранов. Ограничения имитации и пять предложений развития описаны в [отчёте](docs/reports/01-ui-prototype.md). Тестов и тестовых скриптов нет по разделу 7 ТЗ.
