Этапы 2 и 3 доработаны после твоего отчёта: появились локальный смысловой поиск (`backend/app/ai/`), защищённый журнал (`backend/app/domain/audit_chain.py`), зарождающиеся проблемы, `docs/pitch.md`. Оркестратор проверил запуск из свежего клона с GitHub: всё поднимается. Цель этапа — чтобы жюри и сам автор без помощи открыли репозиторий, запустили его по README за 5 минут, и в репозитории не было лишнего.

**Решение заказчика: Docker не нужен.** Запуск только локальный: Python + uv и Node.js.

## Задачи

### 1. Убрать Docker
Удалить `docker-compose.yml`, `.dockerignore`, `backend/Dockerfile`, `frontend/Dockerfile`, `frontend/nginx.conf`. Убрать упоминания Docker и compose из `README.md`, `docs/architecture.md` и `docs/HANDOFF.md`. Поддержку PostgreSQL через `DATABASE_URL` оставить, но описать одной строкой как вариант для промышленной установки.

### 2. Убрать артефакты среды агента
- `frontend/.npmrc` (`cache=.npm-cache`) — это обход ограничений твоей песочницы, у пользователя он не нужен. Удалить.
- Логи `docs/reports/codex-*.log` убрать из Git и добавить в `.gitignore`. Отчёты `docs/reports/*.md` оставить.
- Из пользовательских документов (README, architecture) убрать фразы про «среду агента», «named pipes», `WinError`, «в ограниченной Windows-среде». Это внутренние заметки, не инструкция.
- Vite сейчас запускается с `--host 0.0.0.0` (`dev`, `preview`, `dev:mock`) и открывает приложение в локальную сеть. По умолчанию слушать только localhost.

### 3. README — короткий и рабочий
Переписать `README.md` так, чтобы первый экран отвечал на вопрос «как запустить». Структура:
1. Одна-две фразы о продукте и ссылки на `docs/pitch.md`, `docs/concept.md`, `docs/architecture.md`.
2. **Что нужно установить**: Python 3.12+, uv, Node.js 22+. Дай ссылки на официальные страницы установки и однострочную команду установки uv для Windows (PowerShell) и macOS/Linux.
3. **Запуск** — два терминала:
   - `cd backend` → `uv run python -m app`;
   - `cd frontend` → `npm install` (один раз) → `npm run dev`.
   Открыть `http://localhost:5173`.
4. **Что произойдёт при первом запуске**: создаётся SQLite-база с демо-данными; в фоне скачивается модель поиска (~220 МБ, до минуты). До её загрузки работает поиск по ключевым словам, интерфейс это подписывает.
5. **Роли для демонстрации**: таблица из 4–5 строк — кого выбрать в переключателе и что посмотреть (сотрудник закупок, руководитель закупок, руководитель направления — сводка по компании, администратор).
6. **Сценарий демо**: ссылка на раздел в `docs/pitch.md` (не дублировать длинный список).
7. **Без сервера**: `npm run dev:mock` — статическая версия.
8. **Если что-то не так**: порт занят; сброс демо-данных (`uv run python -m app.seed --reset` или кнопка у администратора); белый экран после обновления — удалить `frontend/node_modules/.vite`; модель не скачалась — работает поиск по ключевым словам.
9. **Проверки** для разработчика: `uv run pytest`, `npm run build`.

Длинные подробности (календарь, правила SLA, mock-режим, структура кода) перенеси в `docs/architecture.md` или удали, если они уже там есть. README — не больше ~120 строк.

### 4. Проверка из чистой копии
Сделай `git clone` текущего локального репозитория во временную папку (вне проекта) и пройди README буквально по шагам: `uv run python -m app`, `npm install`, `npm run build`, `npm run build:mock`, `uv run pytest`. Если что-то не работает из чистой копии — исправь. Временную папку потом удали. Если в песочнице что-то нельзя запустить, запиши это в отчёт как непроверенное, не обходя ограничения изменениями в проекте.
