# ТЗ для Codex · Этап 8.1 · Читаемость графиков на «Аналитике»

## Контекст
Пользователь смотрел «Аналитику» без подсказок и нашёл три места, где график не объясняет себя сам. Это правки только фронтенда (`frontend/src/pages/analytics/*`, `frontend/src/visual.css`), бэкенд не трогать.

## 1. «Здоровье сроков» — легенда не связана с цветами
**Проблема.** Легенда показывает цветные иконки (галочка, часы, треугольник), а полосы — сплошные заливки. Глаз не связывает зелёную иконку-контур с зелёной полосой: пользователь решил, что подписей цветов нет.

**Сделать** (`DeadlineHealth.tsx`):
- В легенде перед каждой подписью — квадрат-образец 12×12 px с той же заливкой, что у сегмента (`health-onTime/soon/overdue`), иконку оставить после образца или убрать. Подписи расширить: «В срок», «Скоро срок (≤ 3 раб. дня)», «Просрочено».
- Легенду поднять над графиком так, чтобы она читалась как подпись к нему (как сейчас — сверху), но визуально в одном блоке с осью.
- Всплывающая подсказка при наведении на сегмент — не системный `title`, а та же своя подсказка, что будет у KPI (п. 3): «Проектирование · Просрочено: 2 обращения. Нажмите, чтобы открыть».

## 2. «Карта повторяющихся проблем» — маленькие плитки пустые
**Проблема.** Плитка «Передача знаний и запуск работ» (≈5 чел.-ч/мес) — узкая полоска без текста; узнать, что это, можно только наведением. На проекторе не узнать никак.

**Сделать** (`ProblemTreemap.tsx`):
- Плитки, в которые не помещается название (порог подобрать по фактическому размеру: ширина < ~120 px или высота < ~56 px), в треемапе не рисовать. Вместо них — одна плитка «Ещё N проблем · X чел.-ч/мес» нейтрального цвета, если она помещается; если и она не помещается — не рисовать.
- Под треемапом — компактный список «Небольшие проблемы»: строка на каждую скрытую плитку — цветной маркер тренда (рост/снижение/без изменений, те же иконки, что в легенде), название, чел.-ч/мес, число обращений и тренд. Строка — кнопка, открывает ту же детализацию кластера, что и плитка.
- Плитка «Ещё N проблем» по клику прокручивает к этому списку/подсвечивает его.
- Средние плитки, где помещается название, но не подпись «чел.-ч/мес · +N обращений», — показывают название и число, без подписи (как сейчас у «Расхождения в номенклатуре»). Проверить, что текст нигде не обрезается посередине слова и не вылезает за плитку.

## 3. KPI-спарклайны — непонятно, что за точка при наведении
**Проблема.** При наведении на спарклайн появляется точка без значения и даты. Непонятно, что это за неделя и сколько.

**Сделать** (`Kpis.tsx`):
- При наведении (и фокусе с клавиатуры) на точку — своя всплывающая подсказка рядом с точкой: «Неделя 13–19 окт · 5 обращений» (для «Сэкономлено» — «… · 12,5 чел.-ч/мес»). Даты — из `data.weekly[index].fromDate/toDate`, формат как в остальном интерфейсе.
- Наведённая неделя выделяется: точка крупнее, тонкая вертикальная направляющая до низа графика.
- Последняя точка (текущая неделя) всегда показана маленькой точкой со значением рядом, чтобы было видно «сейчас» без наведения. Текущая неделя не завершена — в подсказке приписать «(неделя не завершена)».
- Подпись под графиком «10 недель» заменить на диапазон: «10 недель: 8 сен – 12 ноя».
- Клик по точке, как и в таблице, открывает обращения этой недели.

Подсказку сделать одним маленьким компонентом (`ChartTooltip`) и использовать в п. 1 и п. 3. Без новых библиотек.

## 4. «Пользователи и роли» — объяснить, почему нельзя добавить
Добавлять и удалять пользователей вручную не нужно: в компании справочник сотрудников и оргструктура приходят из Битрикс24/1С (см. `docs/architecture.md`, «План интеграций»). Но экран должен это сказать, иначе выглядит недоделанным.

**Сделать** (`UsersPage.tsx`): под заголовком страницы — информационная строка в стиле существующих пояснений: «Сотрудники и подразделения приходят из оргструктуры компании (в пилоте — синхронизация с Битрикс24), поэтому вручную не добавляются и не удаляются. Здесь назначаются роли и замещения на время отпуска.» Если роль здесь на самом деле не меняется — убрать «назначаются роли», оставить то, что реально можно сделать. Никаких новых функций добавления/удаления.

## Общие требования
- Стиль, палитра и типографика — как сейчас. Без иконок-искорок.
- Подсказки не выходят за край карточки и экрана (у правого края — открываются влево).
- Mock-режим работает так же.

## Тесты — строгое ограничение
**Новых тестов не писать.** Никаких тестов фронтенда, e2e, smoke-скриптов, харнессов и скриншот-тестов. Проверка — `npm run build` и `npm run build:mock`.

## Не делать
- Изменения бэкенда, API и других экранов.
- Новые зависимости.
- Коммиты — оркестратор проверит и закоммитит сам.

## Готово, когда
- [ ] В «Здоровье сроков» у каждой подписи легенды есть образец цвета, совпадающий с сегментом.
- [ ] В «Карте проблем» нет плиток без текста; маленькие проблемы перечислены под картой и открывают детализацию.
- [ ] Наведение на точку спарклайна показывает неделю и значение; текущая неделя видна без наведения.
- [ ] «Пользователи и роли» объясняют, откуда берутся сотрудники.
- [ ] `npm run build` и `npm run build:mock` проходят.
- [ ] Короткий отчёт `docs/reports/08.1-chart-readability.md`: что изменено, по файлам.
