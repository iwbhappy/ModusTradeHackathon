# ТЗ для Codex · Этап 5.1 · Мелкие правки по итогам прокликивания

Оркестратор прошёл в браузере все сценарии. Они работают: отказ, возврат «не решена», резервный ответственный при отпуске, загрузка и скачивание файла (права проверяются), SLA и эскалации, колокольчик, мобильная вёрстка. Нашлись три недочёта, все про то, как это выглядит на демо.

## 1. Лента этапов при отказе
`frontend/src/pages/ticket-detail/Tracking.tsx`. Обращение отклонено прямо с рассмотрения (пример: A-010 после отказа). Сейчас этап «В работе» показан как «Пройдено» с галочкой, хотя в работе обращение не было. Правильно: этапы, пропущенные из-за отказа, показывать как «Не потребовалось» (прочерк, не галочка). Отметка «Пройдено» остаётся только для случая, когда обращение реально прошло дальше этого этапа к реализации.

## 2. Лента этапов при возврате автором
После «Не решена — вернуть» (статус «Возвращено автором», пример S-018) этап «Результат» по-прежнему отмечен галочкой с датой прошлой реализации. Правильно: «Результат» снова открыт — номер этапа и «План: <новый срок>». Дату прошлой реализации можно показать мелкой подписью «Прошлый результат: <дата>, возвращён автором».

## 3. Кнопка «Проверить SLA сейчас» показывает «0»
Фоновая проверка уже обработала всё при старте сервера, поэтому на демо кнопка выдаёт «Проверка SLA завершена: 0», и эффекта не видно. Правильно: ответ `POST /api/admin/run-sla-check` дополнить текущей сводкой — сколько обращений сейчас эскалировано, сколько с просроченным первым ответом и решением, сколько закрыто по умолчанию. Тост: «Проверка выполнена. Новых событий: N. Сейчас эскалировано: X, просрочено: Y». Логику самих проверок не менять.
