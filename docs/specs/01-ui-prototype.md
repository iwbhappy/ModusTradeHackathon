# ТЗ для Codex · Этап 1 · Кликабельный UI/UX-прототип «Сигнал»

## 0. Контекст (прочитай перед началом)
- `docs/concept.md`: концепция продукта, роли, изюминки (★ входят в этот этап).
- `docs/source-tz.txt`: исходное ТЗ хакатона ГК «Модус Трейд».
- `docs/source-dataset.txt`: 20 демо-обращений (A-001…A-020) и 6 проверочных сценариев (раздел 4).

Мы делаем внутреннюю систему подачи и рассмотрения обращений сотрудников (проблемы, предложения, отзывы) с AI-слоем. **На этом этапе бэкенда нет**: только фронтенд на моковых данных. Но мок-слой должен быть устроен так, чтобы на этапе 2 его можно было заменить на реальный API без переписывания экранов.

## 1. Цель этапа
Получить кликабельный прототип, на котором можно провести всё демо жюри: все ключевые экраны трёх ролей, работающие сквозные сценарии (создание, назначение, смена статуса, уточнение, отказ, подтверждение решения, аналитика) и визуализированные изюминки ★1–★6. AI-функции на этом этапе **имитируются** детерминированной логикой (поиск по ключевым словам, правила), но выглядят как готовая функция.

## 2. Стек (фиксированный)
- `frontend/`: Vite + React 18 + TypeScript (strict).
- Tailwind CSS с **собственными токенами** (цвета, радиусы, тени заданы в конфиге). Не использовать готовые темы и шаблонные дашборды.
- react-router для маршрутизации.
- Графики: recharts **со стилизацией под нашу палитру** (или простой SVG там, где так чище).
- Иконки: lucide-react, тонкие, 16–18 px.
- Шрифт: **Golos Text** (через `@fontsource/golos-text`, без CDN), моноширинный для ID и чисел: **JetBrains Mono** (`@fontsource/jetbrains-mono`).
- Состояние: React Context или zustand. Сохранение в localStorage, чтобы демо переживало перезагрузку, плюс кнопка «Сбросить демо-данные».

## 3. Визуальный стиль — критично
Продукт для серьёзной инженерной компании из отрасли систем безопасности. Он должен выглядеть как корпоративный рабочий инструмент (уровня Jira, Linear, 1С:ITIL в хорошем исполнении), **а не как AI-стартап с лендинга**.

**Запрещено:** градиенты, glassmorphism, неоновые и фиолетовые «AI»-цвета, эмодзи в интерфейсе, иконки-«искорки» ✨ для AI, огромные скругления (максимум 6 px), «воздушные» карточки с тенями на весь экран, декоративные иллюстрации, анимации ради анимаций, маркетинговые формулировки («Революционный…», «Магия AI»).

**Нужно:**
- Светлая тема по умолчанию: фон `#F5F6F8`, поверхности белые, границы 1 px `#DDE1E6`. Тёмную тему не делать.
- Основной акцент — глубокий сине-стальной (около `#1E3A5F`, действия `#2457A6`). Второй акцент — сигнальный янтарный (около `#C77700`), **только** для просрочек и внимания. Статусы — приглушённые цвета (бейджи с тонкой рамкой и светлой заливкой, без кислотных цветов).
- Плотная информационная вёрстка: таблицы со строками 40–44 px, выравнивание чисел по правому краю, табличные цифры, понятная иерархия заголовков (не больше 3 уровней).
- AI-элементы помечаются сдержанно: небольшая метка «Автоподсказка» или «Анализ системы» и иконка `Sparkle` **не используется**, вместо неё `Wand2` или `ScanSearch`. Подсказки AI всегда можно принять или отклонить.
- Язык интерфейса — русский, деловой, короткий. Даты в формате `14 ноя 2026`, относительные сроки («осталось 2 раб. дня», «просрочено на 1 день»).
- Макет: левый сайдбар (узкий, тёмно-графитовый `#1B2430`), верхняя панель с поиском и **переключателем роли для демонстрации** (Сотрудник / Руководитель / Администратор, плюс выбор конкретного пользователя).
- Адаптив: корректно на 1280–1920 px. Мобильная версия — только экран подачи обращения и карточка «моё обращение» (сотрудник с телефона).

## 4. Данные (мок-слой)
- `frontend/src/data/seed.ts`: все 20 обращений из датасета, **с сохранением ID, текстов, типов, категорий, авторов-ролей, приоритетов, статусов и ответственных**. Дополни их полями: даты создания и этапов (за последние ~10 недель), подразделение автора, подразделение или процесс, к которому относится проблема (для матрицы трения), SLA-дедлайн, история событий, комментарии, оценка «стоимости» (частота + минуты), число присоединившихся.
- Добавь ещё **~40 синтетических обращений** в том же стиле и на те же темы (номенклатура, спецификации, согласования, договоры, документооборот, обучение, ПНР, сервис, IT), чтобы аналитика и кластеры выглядели правдоподобно. Без имён реальных людей, контрагентов и сделок, как требует датасет. Пользователей называть по ролям и подразделениям («Руководитель закупок», «Инженер-проектировщик 2»).
- Сделай 4–6 явных **кластеров повторяющихся проблем** (например, «Неполные заявки на закупку», «Расхождения в номенклатуре», «Непрозрачный статус согласования документов», «Нет единой точки фиксации решений»).
- Справочники: подразделения (Продажи, Закупки, Проектирование, Бухгалтерия, IT-разработка, Сервис и ПНР, Склад и логистика, Администрация, HR), категории из датасета, статусы: `Новое → На рассмотрении → Ожидает уточнения → В работе → Реализовано | Отклонено | Закрыто`, плюс состояние «Возвращено автором» для закрытой петли.
- `frontend/src/api/`: асинхронные функции (`listTickets`, `getTicket`, `createTicket`, `updateStatus`, `addComment`, `joinTicket`, `findSimilar`, `suggestStructure`, `getAnalytics`, …), которые сейчас работают с in-memory/localStorage стором с небольшой искусственной задержкой. **Экраны работают только через этот слой.** Типы — в `frontend/src/types.ts`.

## 5. Экраны

### Сотрудник
1. **Мои обращения**: таблица своих обращений и тех, к которым присоединился. Статус, срок, ответственный, последнее событие. Сверху блок «Требуют вашего действия»: запрошено уточнение, нужно подтвердить решение.
2. **Новое обращение** (одна страница, не многошаговый визард):
   - тип (Проблема / Предложение / Положительный отзыв), категория, «к какому подразделению или процессу относится», текст, предлагаемое решение (необязательно), прикрепление файла (заглушка, показывать имя файла);
   - ★6 **Структуратор**: кнопка «Структурировать текст» превращает текст в блоки «Проблема / Предлагаемое решение / Ожидаемый эффект» и подсказывает категорию и приоритет. Принять или отклонить;
   - ★2 **Похожие обращения**: панель справа, обновляется по мере ввода (debounce). Карточки похожих со статусом и числом присоединившихся, кнопка «У меня то же самое → присоединиться» с полем для своего контекста;
   - ★1 **Стоимость проблемы** (только для типа «Проблема»): «Как часто?» (ежедневно / еженедельно / ежемесячно / разово) и «Сколько времени теряете за раз?» (≈ 15 мин / 30 мин / 1 ч / 2 ч+);
   - перед отправкой показать, **кому уйдёт обращение и в какой срок ответят** (по правилам маршрутизации).
3. **Карточка обращения** (вид автора):
   - ★4 **Трекинг как у посылки**: горизонтальная лента этапов с датами (факт или план), обещанный срок, ответственный;
   - история комментариев и событий, ответ на запрос уточнения;
   - ★5 при статусе «Реализовано»: блок «Что изменилось» и кнопки «Проблема решена» / «Не решена — вернуть». Отказ показывается с мотивировкой.
4. ★5 **Сделано**: лента реализованных улучшений («было → стало», подразделение, сколько человек затронуто, благодарность автору). Видна всем ролям.

### Руководитель / ответственный
5. **Входящие**: очередь назначенных на него и его подразделение. Фильтры: подразделение, категория, статус, приоритет, срок; быстрые вкладки «Новые», «Просрочены» (янтарный акцент), «Ждут уточнения», «В работе». Сортировка по **стоимости проблемы** ★1 как отдельная колонка.
6. **Карточка обращения** (вид ответственного): то же, что у автора, плюс панель действий:
   - сменить статус, переназначить (с причиной), запросить уточнение;
   - отклонить → обязательная мотивировка с шаблонами;
   - реализовать → обязательное поле «Что изменилось»;
   - «Черновик ответа» (имитация AI): вставляет корректный деловой текст, который можно отредактировать;
   - блок «Связанные обращения / кластер» с суммарной стоимостью и списком затронутых подразделений.
7. **Аналитика**:
   - KPI-строка: доля рассмотренных, медиана времени до первого ответа, доля с зафиксированным результатом, реализовано за период, **«подтверждено авторами»** ★5;
   - распределение по типам, категориям и статусам; динамика по неделям;
   - **Повторяющиеся проблемы**: таблица кластеров (название, число обращений, затронутые подразделения, ≈ чел.-часов/мес ★1, тренд), клик открывает список обращений;
   - ★3 **Матрица межотдельного трения**: тепловая карта «подразделение автора × подразделение или процесс проблемы», клик по ячейке открывает отфильтрованный список;
   - **SLA**: просроченные по подразделениям.
   - Фильтр периода: 30 / 90 дней / всё время.

### Администратор
8. **Категории и маршрутизация**: таблица правил «категория (+ подразделение) → ответственный, резервный ответственный, SLA первого ответа и решения». Редактирование в модальном окне. Показать сценарий «основной ответственный отсутствует → уходит резервному» (переключатель «в отпуске» у пользователя).
9. **Пользователи и роли**: список с ролями и подразделениями, кратко описанная матрица доступа (кто что видит: автор — свои, ответственный — свои назначения и своё подразделение, руководитель — подразделение и аналитика, админ — настройки).

## 6. Обязательные сквозные сценарии (должны полностью кликаться)
1. Сотрудник создаёт проблему, видит похожее обращение, присоединяется к нему. Отдельно создаёт новое — оно уходит ответственному по правилу.
2. Руководитель открывает «Входящие», берёт обращение в работу, запрашивает уточнение. Сотрудник отвечает. Руководитель реализует его с текстом «Что изменилось». Сотрудник подтверждает решение. Обращение появляется в «Сделано».
3. Руководитель отклоняет обращение с мотивировкой (как A-017). Автор видит причину.
4. Ответственный «в отпуске» — новое обращение уходит резервному.
5. Аналитика: найти просроченные, открыть кластер, кликнуть по ячейке матрицы трения.

## 7. Тесты — ограничение
**Тесты на этом этапе не писать.** Ни юнит-тестов, ни e2e, ни smoke-скриптов, ни тестовых харнессов. Проверка готовности — только `npm run build` и `tsc --noEmit` без ошибок, плюс ручная прокликиваемость сценариев.

## 8. Что не делать
- Не создавать бэкенд, Docker, CI, линтер-конфиги сверх стандартного шаблона Vite.
- Не подключать внешние API и LLM.
- Не делать лендинг, онбординг-туры, тёмную тему, i18n.
- Не плодить абстракции «на будущее» сверх мок-слоя `src/api`.
