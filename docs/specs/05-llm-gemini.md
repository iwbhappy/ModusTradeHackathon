# ТЗ для Codex · Этап 5 · Генеративные функции на Gemini

## Контекст
Все AI-функции скрыты за интерфейсом `AIProvider` (`backend/app/ai/provider.py`). Поиск похожих и кластеры работают на локальных эмбеддингах (`SemanticProvider`) и **остаются локальными**. Структуратор текста и черновики ответов сейчас на правилах (`RuleBasedProvider`) и дают шаблонный текст — это самое слабое место демо.

Пользователь положил ключ Gemini в **корневой** `.env` проекта под именем `GEMINI_API`. Файл в `.gitignore`. **Бюджет на аккаунте — около $3**, поэтому экономия — жёсткое требование.

## Цель
Подключить LLM-провайдер на Gemini для трёх функций, с честной маркировкой в интерфейсе, защитой бюджета и автоматическим возвратом к правилам при любой проблеме.

## 1. Провайдер
- `backend/app/ai/llm.py`: `GeminiProvider`, вызовы REST API Gemini (`generateContent`) через `httpx` (уже в зависимостях). Без новых SDK.
- Модель по умолчанию: `gemini-flash-lite-latest` (`LLM_MODEL` в настройках). Ключ: `GEMINI_API_KEY`, также принимать имя `GEMINI_API`. Настройки читают и корневой `.env`, и `backend/.env`.
- `LLM_PROVIDER=gemini|none`. Без ключа или при `none` всё работает на правилах, как сейчас.
- Ответы структурированные: `responseMimeType: application/json` + `responseSchema`. Температура низкая (0.2–0.3), `maxOutputTokens` ограничен (структуратор ~400, черновик ~300, сводка ~800). Таймаут 15 с.
- Любая ошибка (сеть, 4xx/5xx, превышен лимит, невалидный JSON) → тихий возврат к `RuleBasedProvider` с записью в лог. Пользователь не видит трейсбеков.
- Ключ никогда не логировать и не отдавать на фронтенд.

## 2. Защита бюджета
- Кеш ответов по хешу (функция + модель + входные данные) — в таблице БД (`llm_cache`, миграция Alembic). Повторный клик по той же кнопке не тратит деньги.
- Дневной лимит вызовов `LLM_DAILY_LIMIT` (по умолчанию 200). После лимита — правила.
- Учёт токенов из `usageMetadata` каждого ответа (вход/выход) в той же таблице или отдельной; `GET /api/ai/status` дополнительно отдаёт `llm: {provider, model, enabled, callsToday, tokensToday}`.
- LLM вызывается **только по явному действию пользователя** (кнопка). Никаких вызовов на каждое нажатие клавиши, при загрузке страниц или в фоне.
- Во время разработки делай **не больше ~20 реальных вызовов** суммарно. Для отладки формы запроса используй кеш и правила.

## 3. Функции

### 3.1 Структуратор (кнопка «Структурировать текст» в форме нового обращения)
Вход: текст сотрудника, выбранные категория и подразделение, список допустимых категорий и приоритетов. Выход (JSON): `title` (≤ 80 символов), `problem`, `solution` (если в тексте нет — предложить одно конкретное), `effect`, `category` (строго из списка), `priority`. Язык — русский, деловой, без воды, без выдумывания фактов, которых нет в тексте. Промпт должен учитывать контекст компании (инженерные и слаботочные системы безопасности: СКУД, видеонаблюдение, ОПС, проектирование, закупки, ПНР, сервис).

### 3.2 Черновик ответа ответственного (кнопка «Черновик ответа»)
Вход: заголовок и текст обращения, категория, выбранный новый статус (уточнение / в работе / реализовано / отклонено), **до 3 похожих уже рассмотренных обращений с их результатом** (бери из локального поиска — это делает черновик предметным: «в похожем случае S-002 сделали так…»). Выход: 2–4 предложения от лица ответственного. Для «Ожидает уточнения» — конкретные вопросы по сути обращения. Для «Реализовано» — черновик «что изменилось», который руководитель обязан отредактировать (подсказка в UI).

### 3.3 Сводка для руководителя (новое, на экране «Аналитика»)
Кнопка «Сформировать сводку» (доступна руководителю, видящему аналитику). Вход: агрегаты, которые уже считает `analytics.summary` (KPI, топ кластеров с чел.-часами и трендом, зарождающиеся проблемы, просрочки по подразделениям) — **только агрегаты и заголовки, без текстов обращений и без имён**. Выход (JSON): 3–5 пунктов «что важно на этой неделе» и 2–3 рекомендованных действия с указанием, на какой кластер или подразделение они направлены. Отображается панелью под KPI; кешируется до изменения данных.

## 4. Приватность и честная маркировка
- В интерфейсе рядом с результатом LLM — сдержанная подпись: «Сформировано Gemini (внешний сервис) · проверьте перед сохранением». Для результатов правил — «Автоподсказка по правилам». Иконку-искорку не использовать (см. стиль этапа 1).
- Перед отправкой в Gemini маскировать email, телефоны и номера, похожие на паспортные/ИНН (простые регулярки). Описать это в `docs/architecture.md`.
- Поиск похожих и кластеры не трогать: они локальные, подпись «данные не покидают контур» остаётся только у поиска.
- В `docs/architecture.md` раздел «AI-слой» дополнить: какие функции идут во внешний сервис, что именно передаётся, как отключить (`LLM_PROVIDER=none`), и путь для промышленной версии — та же реализация провайдера на локальной открытой модели (например, Gemma) без изменения кода экранов.
- В `docs/pitch.md` поправить раздел ограничений и вопросов: LLM теперь есть, но только по кнопке, на синтетических данных, с маскировкой и отключаемый.

## 5. Фронтенд
- Структуратор и черновик: показывать источник (`source: "llm" | "rules"` в ответе API) и подпись из п. 4.
- Новая панель «Сводка для руководителя» в аналитике, в общем стиле (без градиентов, плотная типографика). Состояния: пусто (кнопка), загрузка, результат, ошибка/лимит (сообщение и результат правил, если есть).
- Mock-режим: LLM недоступен, кнопка сводки скрыта или показывает «доступно с сервером».

## 6. Тесты
Не больше **2** новых pytest без сети: возврат к правилам при отсутствии ключа или ошибке, и маскировка персональных данных. Реальные вызовы Gemini в тестах запрещены. Никаких харнессов и smoke-скриптов.

## 7. Не делать
- Не отправлять в LLM поиск похожих, кластеры, тексты комментариев и вложения.
- Не добавлять стриминг, чат, агентов, фоновые вызовы.
- Не менять существующие экраны, кроме перечисленного.
- Не коммитить. Оркестратор проверит и закоммитит сам.
