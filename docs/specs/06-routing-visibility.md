# ТЗ для Codex · Этап 6 · Получатель по категории, видимость, роль администратора

## Контекст
Пользователь проверил систему и прислал три замечания. Оркестратор нашёл причины. Объём — только то, что ниже.

## 1. «Создал обращение за сотрудника, а у руководителя его не видно»

### Причина
`frontend/src/store.ts`, `selectRole`: при переключении роли берётся **первый пользователь этой роли по списку** (`catalog.users.find(...)`). Для роли «Руководитель» это `head-5` «Руководитель: Сервис и ПНР». Обращение при этом ушло, например, Руководителю закупок — и пользователь смотрит не его очередь. Вторая причина: руководитель подразделения видит только обращения, **назначенные** людям своего подразделения, и не видит обращения **своих сотрудников**, ушедшие в другой отдел.

### Что сделать
- Переключатель роли запоминает последнего выбранного пользователя для каждой роли (localStorage). По умолчанию: Сотрудник → `employee-1` (Сотрудник закупок), Руководитель → `manager-1` (Руководитель закупок), Администратор → `admin`.
- После отправки обращения в карточке (и в тосте) показать «Обращение получил: <имя>» и, только в демо-режиме, ссылку «Открыть как <имя>» — она переключает демо-пользователя на получателя и открывает это обращение. Это прямо закрывает сценарий демонстрации.
- Руководитель подразделения (`is_department_head`) дополнительно видит обращения, **автор которых из его подразделения**, — только чтение (без действий ответственного, если обращение назначено не ему). Во «Входящих» — отдельная вкладка «От моих сотрудников». Права — на сервере (`domain/permissions.py`: `can_read`, `visible_clause`), действия (`can_manage`) не расширять.

## 2. Получатель сразу по категории
Сейчас получатель виден только внизу формы. Нужно:
- При выборе категории сразу подставлять поле «К какому подразделению относится» — подразделение основного ответственного по правилу этой категории (если пользователь ещё не менял поле вручную).
- Сразу под категорией и подразделением показывать блок **«Получатель»**: имя и должность ответственного по правилу, сроки первого ответа и решения, пометка, если назначен резервный из-за отпуска. Использовать существующий `GET /api/routing/preview`.
- Кнопка «Изменить получателя» раскрывает выбор из руководителей (с подразделением; находящиеся в отпуске — недоступны и подписаны). Можно вернуть «по правилу».
- Сервер: `TicketDraft` принимает необязательный `assigneeId`. Если задан — проверить, что это существующий руководитель не в отпуске, иначе 422 с понятным сообщением; назначить его, сроки взять по правилу категории; в журнал — событие «Получатель выбран автором: <имя> (по правилу — <имя>)». Если не задан — как сейчас, по правилам.
- Нижний блок «Обращение получит…» перед кнопкой отправки оставить, синхронно с выбором.

## 3. Администратор видит всё
Решение заказчика: администратор — верх иерархии и должен видеть всё.
- Администратор читает **все** обращения целиком (текст, комментарии, история, вложения, участники), видит **всю аналитику по компании** (как руководитель направления, включая сводку и зарождающиеся проблемы) и может **переназначать** обращения. Решения по существу (статусы, отказ, реализация) остаются за ответственным — это сохраняет ответственность исполнителя; переназначение пишется в журнал.
- В навигации администратора добавить «Все обращения» (общий реестр с фильтрами — переиспользовать таблицу «Входящих») и «Аналитика».
- Сервер: `permissions.py` — `can_read` для администратора `True`, `visible_clause` — все, `analytics_clause` — вся компания; переназначение разрешить администратору. Поиск похожих администратору разрешить.
- Обновить матрицу доступа на экране «Пользователи и роли», `docs/architecture.md` (раздел «Права»), `docs/pitch.md` (вопрос «Кто видит обращения?» и все места, где сказано, что администратор не видит содержимое), README (таблица ролей).
- Тест `test_domain.py`, который проверяет, что администратор **не** видит обращение, — инвертировать (администратор видит, сотрудник по-прежнему нет). Новых тестов не добавлять, кроме одного: руководитель подразделения видит обращение своего сотрудника, назначенное в другой отдел, но не может им управлять.
