# ТЗ для Codex · Этап 7 · Короткий отчёт за период и визуальная переработка

## Контекст
Отзыв заказчика:
1. Руководители и администратор не будут проверять каждое обращение. Им нужен **короткий отчёт за период**: что изменилось за неделю (месяц и т.д.), смежные обращения объединены в группы, по каждой — коротко «что сделано», при необходимости раскрывается полный список.
2. Никто не хочет считать вручную — нужна **полезная инфографика и интерактивные элементы**.
3. Дизайн слишком **серый и блёклый**: непонятно, где заголовок и куда смотреть в первую очередь.

Этап 6 (получатель по категории, видимость, администратор видит всё) уже принят. Прочитай `git log` и `docs/specs/06-routing-visibility.md`.

## Часть A. Короткий отчёт за период

### Экран «Отчёт» (новый пункт навигации у руководителей и администратора, первым в списке)
Сверху — выбор периода: **Неделя · 2 недели · Месяц · Квартал · Свой период** (два поля дат). По умолчанию — неделя. Область данных: руководитель подразделения — своё подразделение; руководитель направления и администратор — вся компания (как в аналитике).

Структура экрана сверху вниз — порядок важен, это и есть «куда смотреть в первую очередь»:

1. **Главное за период** — 4 крупные карточки с дельтой к предыдущему такому же периоду (↑/↓, цвет по смыслу: рост реализованных — хорошо, рост просрочек — плохо):
   - поступило обращений;
   - решено (реализовано + отклонено с мотивировкой);
   - подтверждено авторами;
   - сэкономлено ≈ чел.-ч/мес (сумма «стоимости» реализованных за период).
2. **Требует внимания** — компактный список с иконками и количеством, каждый пункт кликабелен (открывает отфильтрованный список): эскалировано, просрочено, возвращено авторами, ждут ответа автора дольше 3 дней, новые зарождающиеся проблемы. Если пусто — «Всё под контролем» одной строкой.
3. **Что сделано — по группам.** Обращения, по которым за период было движение (создано, реализовано, отклонено, закрыто), сгруппированы по кластеру повторяющейся проблемы; не попавшие в кластер — по категории. Для каждой группы — карточка:
   - название группы, затронутые подразделения;
   - счётчики: новых · реализовано · отклонено · в работе;
   - **«Коротко»** — 1–2 предложения, что сделано в группе за период;
   - кнопка «Показать обращения (N)» раскрывает список: ID, заголовок, статус, «что изменилось»/причина отказа одной строкой, ссылка на карточку.
   Группы отсортированы по значимости: сначала с реализованными изменениями, затем по сумме чел.-часов.
4. **Новые темы** — зарождающиеся проблемы, впервые замеченные в этом периоде (переиспользовать существующую логику).

Кнопка **«Печать / PDF»** — печатная вёрстка через `@media print` (без навигации, без кнопок, все группы раскрыты). Отдельной генерации PDF не делать.

### «Коротко» по группам
- Без LLM (`LLM_PROVIDER=none` или ошибка): собрать из полей «что изменилось» реализованных обращений группы — первое предложение каждого, не больше двух, плюс счётчики («Реализовано 2 изменения: …; ещё 3 в работе»).
- С Gemini: кнопка **«Сформулировать кратко»** над списком групп — **один вызов на весь отчёт**: на вход только названия групп, счётчики и тексты «что изменилось»/причин отказа (без текстов жалоб, без имён), на выход JSON `{groupId: "1–2 предложения"}`. Кешировать по хешу данных через существующий `llm_cache`. Подпись источника — как в этапе 5.

### Сервер
- `GET /api/reports/period?from=YYYY-MM-DD&to=YYYY-MM-DD` — всё для экрана одним ответом: главное с дельтами, «требует внимания», группы со списками обращений (только поля для списка), новые темы. Права — те же, что у аналитики (`analytics_clause`).
- `POST /api/reports/period/summary` — генерация «Коротко» через LLM по тем же параметрам.
- Агрегация — SQL, как в `analytics.py`. Расчёт «предыдущего периода» — та же длина сразу перед выбранным.

## Часть B. Визуальная переработка

Цель: интерфейс остаётся строгим корпоративным инструментом, но становится **контрастным и иерархичным** — с первого взгляда понятно, что главное. Запрет на градиенты, эмодзи, glassmorphism, «AI-фиолетовый» и огромные скругления остаётся.

### B1. Палитра и токены (заменить текущие в `tailwind.config.js` / `styles.css`)
- Фон страницы `#E9EEF4` (голубовато-серый, заметно темнее белых карточек), карточки `#FFFFFF` с тенью `0 1px 2px rgba(16,24,40,.06), 0 1px 3px rgba(16,24,40,.10)` и границей `#D5DDE7`.
- Текст: основной `#0F1B2D`, вторичный `#4A5568`, приглушённый `#718096`. Ни один значимый текст светлее `#718096`.
- Бренд: сайдбар `#13233A`, активный пункт — подложка `#1F3A5F` + левая полоса 3 px `#3B82F6`. Основное действие `#1D5FD1` (hover `#174EAD`).
- **Статусы — цвет с заливкой, а не серая рамка** (бейдж: светлая заливка + насыщенный текст + точка):
  Новое — синий `#1D5FD1` на `#E3EDFC`; На рассмотрении — бирюзовый `#0E7C86` на `#DDF3F4`; Ожидает уточнения — янтарный `#9A5B00` на `#FDF1D8`; В работе — индиго-синий `#3348A8` на `#E6E9FA`; Реализовано — зелёный `#17803D` на `#DFF5E6`; Закрыто — серо-зелёный `#3F6B4E` на `#E8F0EA`; Отклонено — серый `#4A5568` на `#EDF0F4`; Возвращено автором — оранжевый `#B4461B` на `#FCE7DC`; Эскалировано — красный `#B42318` на `#FDE4E2`.
- Состояния (с иконкой и подписью, не только цветом): хорошо `#0CA30C`, внимание `#FAB219`, серьёзно `#EC835A`, критично `#D03B3B`.
- **Категориальная палитра графиков — строго в этом порядке, не перемешивать** (проверена на различимость при цветовой слепоте): `#2A78D6`, `#EB6834`, `#1BAF7A`, `#EDA100`, `#E87BA4`, `#008300`, `#6250D6`, `#E34948`. Больше 8 серий — сворачивать в «Прочие». Цвет закреплён за сущностью (подразделение, кластер), а не за позицией: фильтр не перекрашивает оставшиеся.
- **Последовательная шкала** (тепловая карта, интенсивность): синяя `#CDE2FB → #9EC5F4 → #6DA7EC → #3987E5 → #256ABF → #184F95 → #0D366B`.

### B2. Типографика и иерархия
- Заголовок страницы 26–28 px, 700, основной цвет; подзаголовок 15 px вторичным.
- Заголовок панели 16 px, 650, с иконкой слева; у ключевых панелей — тонкая цветная полоса сверху 3 px (цвет по смыслу: внимание — янтарный, результат — зелёный).
- Цифры KPI 32–36 px, 700, моноширинные табличные; подпись над ними 13 px, 600, в верхнем регистре с разрядкой.
- Текст в таблицах 14 px, вторичные строки 13 px. Минимальный размер шрифта во всём интерфейсе — 12 px.
- Вертикальный ритм: отступ между блоками 24 px, внутри панели 20 px.

### B3. Инфографика — только полезная и интерактивная
Каждый график отвечает на конкретный вопрос руководителя. У всех — подсказка при наведении, клик открывает отфильтрованный список обращений (переиспользовать существующий drilldown), подписи осей и легенда при ≥ 2 сериях, рядом — переключатель «Таблица» для доступности. Два масштаба по оси Y на одном графике — запрещено.

На экране «Аналитика» заменить простые списки «По типам / статусам / категориям» на:
1. **KPI-карточки** (вместо нынешней строки): значение, дельта к прошлому периоду с цветной стрелкой, мини-спарклайн за 10 недель. *Вопрос: «Мы работаем лучше или хуже?»*
2. **Воронка обработки**: поступило → рассмотрено → в работе → реализовано → подтверждено автором, с процентом перехода между этапами (ординальная синяя шкала, шаги 250→600). *Вопрос: «Где обращения застревают?»*
3. **Здоровье сроков по подразделениям**: горизонтальные столбцы с накоплением на подразделение ответственного — «в срок» (зелёный), «скоро срок» (янтарный), «просрочено» (красный), с подписью числа; сортировка по просроченным. *Вопрос: «Какой отдел не справляется?»*
4. **Карта повторяющихся проблем (treemap)**: площадь — ≈ чел.-ч/мес, цвет — тренд (рост — тёплый, снижение — холодный, нейтраль — серый), подпись — название кластера и часы. Клик — список. *Вопрос: «Что чинить первым?»* Таблицу кластеров оставить ниже как детализацию.
5. **Динамика**: линии «поступило» и «решено» по неделям + заливка разницы (растёт ли очередь), перекрестие с подсказкой. *Вопрос: «Успеваем ли разбирать поток?»*
6. Матрицу трения оставить, перекрасив в последовательную синюю шкалу; подписи значений — тёмным текстом на светлых ячейках и белым на тёмных.

Можно использовать `recharts` (уже разрешён этапом 1) или SVG вручную — главное, единый стиль: тонкие линии 2 px, скругление концов столбцов 4 px, зазор 2 px между сегментами, сетка едва заметная (`#E2E8F0`).

### B4. Остальные экраны — точечно
- «Входящие» и «Все обращения»: строка просроченного — тонкая красная полоса слева и красный срок; приоритет «Высокий» — заметный бейдж; вкладки с цветными счётчиками (просрочено — красный).
- «Мои обращения»: блок «Требуют вашего действия» — янтарная полоса и крупнее.
- Форма нового обращения: блок «Получатель» визуально выделен (светло-синяя подложка); основная кнопка «Отправить» — бренд-синяя, крупная.
- Карточка обращения: текущий этап ленты — синий, пройденные — зелёные, просроченный плановый — красный.
- «Сделано»: зелёная полоса и иконка у карточек, блок «Стало» — светло-зелёная подложка.

## Ограничения
- Мобильная вёрстка формы и карточки сотрудника не должна сломаться.
- Mock-режим: отчёт работает на локальных данных (без LLM), графики тоже.
- Реальных вызовов Gemini — **не больше 3** за этап.
- Тестов — **не больше 1** нового (агрегация отчёта: группировка и дельта к прошлому периоду), без сети. Никаких харнессов и smoke-скриптов.
- Не коммитить.
