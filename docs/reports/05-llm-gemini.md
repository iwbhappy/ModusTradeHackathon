# Этап 5 · Генеративные функции Gemini

## Реализация

- `GeminiProvider` вызывает REST `generateContent` через httpx, без SDK. По умолчанию `gemini-flash-lite-latest`, температура 0.2, таймаут 15 с, пределы выходных токенов 400/300/800. JSON-схемы и серверная валидация ограничивают поля, категории, приоритеты и адресатов рекомендаций.
- Ключ принимается как `GEMINI_API_KEY` или `GEMINI_API` из корневого `.env`, `backend/.env` и окружения. Он хранится как `SecretStr`, используется только в заголовке API; ключ не выводился, не логировался, не передаётся клиенту и не включён в изменения Git.
- Миграция `a412c7e8d901` создаёт постоянный кеш `llm_cache` и дневной учёт `llm_usage`. Ключ кеша: функция, модель, версия промпта, замаскированный вход. Лимит по умолчанию — 200 попыток за день UTC, включая ошибки. Резервирование фиксируется до вызова. Из `usageMetadata` учитываются входные и выходные токены. Сброс демо сохраняет кеш и расходы.
- Структуратор получает категорию, подразделение и допустимые значения. Черновик получает текст обращения и до трёх результатов локального поиска среди рассмотренных обращений. Сводка получает только агрегаты и заголовки в серверной области доступа руководителя; имена пользователей удаляются.
- Перед отправкой маскируются email, телефоны и номера, похожие на паспортные/ИНН. В логах ошибок — только функция и тип исключения. Любая ошибка генерации, отсутствие ключа, `LLM_PROVIDER=none` или исчерпанный лимит дают правила с честной подписью.
- Клиент показывает `source: llm|rules`, кеш и сообщение о резервном режиме. Добавлена панель сводки под KPI: пустое состояние, загрузка, результат, ошибка/лимит. Для реализованного обращения есть подсказка отредактировать черновик и указать подтверждённые изменения. В mock структура и ответ работают на правилах, сводка помечена «Доступно с сервером».
- Поиск похожих и кластеры остаются локальными. Ввод текста, открытие страниц и фоновые задачи не вызывают LLM. Обновлены README, архитектура, pitch, HANDOFF и пример настроек. Коммитов нет.

## Реальные вызовы и бюджет

За разработку выполнено **3 реальных запроса Gemini**, все успешны: по одному на структуратор, черновик и сводку. Каждая повторная отправка через API вернулась с `source=llm`, `cached=true` без дополнительных вызовов. Тесты не обращались к сети.

Счётчик БД за 10 ноября 2026 UTC изменился с 0 до 3 попыток. Расход из `usageMetadata`: **2 053 входных + 426 выходных = 2 479 токенов**. Платных повторов, автоматических вызовов и запросов с реальными персональными данными не было. Остальные ручные проверки выполнялись с `LLM_PROVIDER=none` либо лимитом 0; счётчик остался равен 3.

## Проверки и ограничения

- Миграция применена; три функции проверены ручными API-запросами с реальным Gemini, затем повторены из кеша. `/api/ai/status` показал модель, enabled, 3 вызова и 2 479 токенов.
- При `LLM_PROVIDER=none` все три функции вернули HTTP 200 и `source=rules`. При лимите 0 новый запрос вернул правила и сообщение о лимите. Сотрудник не получил доступ к сводке (403).
- Ровно **2 новых pytest без сети**: отсутствие ключа/отключение, ошибка и невалидный JSON, постоянный кеш и лимит в одном тесте; маскировка вложенных данных во втором. Всего **17 passed** командой `uv run pytest` с `UV_CACHE_DIR` в разрешённой локальной папке. Со стандартным кэшем uv команда блокируется правами окружения; настройки проекта для обхода не добавлялись.
- `npm run build` — успешно, включая `tsc --noEmit`. Отдельная проверка TypeScript также прошла.
- `npm run build:mock` — TypeScript проходит, Vite останавливается до загрузки конфигурации: запуск дочернего esbuild запрещён окружением (`spawn EPERM`). Итоговая mock-сборка **не подтверждена**; требуется повторить команду вне ограниченной среды. Браузерная приёмка не выполнялась.
- Регулярки не обеспечивают полную анонимизацию; модель может ошибаться, результат требует проверки человеком. Дневной лимит относится к этой БД, не ко всему аккаунту Gemini; при сетевом сбое расход токенов может остаться неизвестным. Приложение рассчитано на один процесс; ограничения нескольких процессов и путь к локальной Gemma описаны в архитектуре.
