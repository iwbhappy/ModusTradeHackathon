# Этап 2 · Бэкенд и реальная логика

Реализован MVP по `docs/specs/02-backend.md`: frontend по умолчанию работает через FastAPI и БД. Статический mock сохранён отдельным адаптером. Архитектура, ER-диаграмма, машина состояний, матрица прав, безопасность и план интеграций находятся в [architecture.md](../architecture.md), запуск и демо — в корневом [README](../../README.md).

## Что сделано

**Backend.** Python 3.12+, FastAPI, Pydantic v2, typed ORM SQLAlchemy 2 и Alembic. Зависимости и pytest закреплены `pyproject.toml` / `uv.lock`. Локальная БД — SQLite; `DATABASE_URL` переключает на PostgreSQL через psycopg. Миграция создаёт users, departments, categories, routing_rules, tickets, ticket_participants, comments, ticket_events, attachments, notifications, clusters и ticket_clusters. Диалектный SQL и SQLite-специфичные запросы не используются.

**Один сид.** Все 60 обращений перенесены в `data/seed.json`, включая исходные A-001…A-020 и переписанные на этапе 1.1 S-001…S-040, результаты, участников и историю. Даты записаны смещениями в днях. Старые отдельные frontend-датасеты удалены. Категорий теперь девять; прежняя категория сохранена отдельно в каждом обращении и в таблице сопоставления. Начальные назначения и исходные тексты сохранены.

**Доступ.** Демо-вход выдаёт JWT HS256 с ограниченным сроком; роль, область доступа и отпуск читаются из БД. Проверки централизованы в `domain/permissions.py`. Сотрудник получает полную карточку только своего или присоединённого обращения. Ответственный — свои назначения; руководитель подразделения — назначения своего подразделения. Компанейская аналитика разрешена только руководителю направления (`manager-2`) с отдельным флагом. Администратор не видит полные карточки и вложения, имеет настройки и агрегаты. «Похожие» скрывают переписку и контекст других участников; «Сделано» публикует результат для всех ролей.

**Workflow.** Единственная машина состояний находится в `domain/workflow.py`: разрешённые переходы, роль исполнителя и обязательные пояснения. Недопустимое действие возвращает 409 на русском. Автор отвечает на уточнение, подтверждает реализацию либо возвращает её с новым сроком. Закрыть за автора вручную ответственный не может.

**Назначение.** Категория + подразделение → категория → общее правило. Отпуск основного включает резервного. При отсутствии обоих назначается руководитель подразделения или направления, причина сохраняется в аудите. Если оргструктура повреждена и в ней вообще нет ответственных, регистрация блокируется; записи без владельца не создаются.

**SLA.** Рабочие дни и часы учитывают конфиг календаря РФ 2026–2027, перенесённые выходные и рабочую субботу. Есть фоновая asyncio-проверка с настраиваемым интервалом и защищённый административный ручной запуск. Система напоминает за рабочий день до срока, сообщает руководителю о просрочке первого ответа, эскалирует решение с задержкой больше трёх рабочих дней. Руководитель направления получает доступ к эскалированной карточке. Реализация без ответа автора закрывается через пять рабочих дней как подтверждённая по умолчанию; явные и автоматические подтверждения считаются отдельно.

Относительные подписи срока в HTTP-режиме также вычисляет сервер по этому календарю; старый клиентский подсчёт только по выходным остаётся запасным вариантом для mock.

**Аудит и уведомления.** События содержат автора, время, поле, старое и новое значение статуса/назначения. Запись обращения, событие и внутрисистемное уведомление фиксируются одной транзакцией до отправки ответа. Версия строки защищает от потерянных конкурентных изменений. Колокольчик получает уведомления и точный SQL-счётчик непрочитанных, помечает выбранное уведомление прочитанным и открывает карточку. Повторные SLA-проверки не дублируют напоминания одного цикла.

**Вложения.** Файлы реально загружаются, сохраняются в `backend/storage/` и скачиваются через API с проверкой прав. Лимит — 10 МБ; расширения — pdf, png, jpg, docx, xlsx, txt. Загрузка потоковая, имя на диске случайное, пути проверяются. До регистрации обращения файл доступен только загрузившему сотруднику, после привязки — по правам карточки. `Storage.save/open` отделяет локальное хранение от будущего S3.

**AI.** На сервер перенесены нормализация, стоп-слова, IDF, вес заголовка, бонусы контекста, объяснения совпадений, структуратор и черновики. Они работают за интерфейсом `AIProvider`, принимающим текст, категорию, подразделение и кандидатов. Реализация — `RuleBasedProvider`; сетевых обращений к LLM нет.

**Аналитика и Excel.** KPI, распределения, медиана и среднее, недельная динамика, кластеры, матрица и SLA рассчитываются SQL-запросами. Клиент не получает весь реестр для построения аналитики: детализация запрашивается отдельно с областью доступа и пагинацией. XLSX через openpyxl выгружает разрешённый пользователю реестр за период; формулоподобный текст экранируется.

**Frontend.** Фасад сохраняет прежние сигнатуры операций; реализация выбирается через `VITE_API_MODE`: HTTP по умолчанию, mock — для статики. Добавлены Vite proxy, подпись демо-входа и будущего SSO, колокольчик, метка эскалации, реальный выбор/загрузка/скачивание файлов, XLSX и административная кнопка запуска SLA. Ошибки 403/409/422 выводятся короткими русскими сообщениями. Визуальная палитра и существующие экраны сохранены.

**Развёртывание.** `uv run python -m app` применяет миграции, загружает только пустую БД и запускает API одним процессом. Явные команды миграции/сида/uvicorn из ТЗ также сохранены. Добавлены Dockerfile бэкенда и фронтенда, nginx с SPA fallback и API proxy, compose с PostgreSQL и постоянными томами БД/вложений.

## Как проверено

Автоматическая проверка ограничена ровно **12 pytest-тестами доменной логики** в `backend/tests/test_domain.py`: недопустимое закрытие, обязательные мотивировка/результат/вопрос, запрет подтверждения за автора, чужая карточка сотрудника, отсутствие доступа администратора, доступ участника, резервное назначение, оба ответственных отсутствуют, общее правило и календарь с праздником/рабочей субботой. Тестов API-эндпоинтов, frontend, e2e, smoke-скриптов, харнессов и тестов сида не создавалось.

Финальные команды:

| Проверка | Результат |
| --- | --- |
| `uv sync` | Успешно, lock-файл актуален |
| `uv run alembic upgrade head` | Успешно на SQLite |
| `uv run python -m app.seed --reset` | Загружено 60 обращений |
| `uv run alembic check` | `No new upgrade operations detected` |
| `uv run pytest` | **12 passed**, без предупреждений |
| `npm run build`, HTTP | Успешно, ошибок TS нет |
| Сборка с `VITE_API_MODE=mock` | Успешно, отдельный mock-бандл без HTTP-зависимости от сервера |
| `npx tsc --noEmit` | Успешно отдельным запуском |
| `npm run format` | Успешно; Python-код также отформатирован |
| `uv run python -m app` | API стартует, существующая БД сохраняется |
| Swagger `/docs` | HTTP 200 |

В интерактивном ручном API-сеансе, без сохранения проверочных программ, выполнены следующие действия:

- Создано обращение N-83F0F1382A; назначено руководителю закупок, в истории появились регистрация и назначение.
- Через разные JWT пройдена цепочка **Новое → В работе → Ожидает уточнения → На рассмотрении после ответа автора → Реализовано → Закрыто после подтверждения**.
- Под токеном сотрудника прямой запрос A-017 дал **403** с сообщением «Нет доступа к содержимому этого обращения». Доступ к присоединённым обращениям при этом сохраняется.
- Под токеном администратора запрос полной созданной карточки дал **403**.
- Загружен `demo.txt` (59 байт), получено скачивание **200**. Файл затем прикреплён к новому обращению через `attachmentIds`; метаданные сохранились после перезапуска API.
- При отпуске руководителя закупок и резервного ответственного создано N-81F52254C2 с назначением **manager-2** и событием о резервном правиле. Отпуска затем восстановлены.
- XLSX вернулся с **200**, корректным MIME и ZIP-сигнатурой `504b0304`.
- Выполнен административный сброс до 60 исходных обращений и ручные SLA-проверки. После обработки повторные проверки возвращали `processed: 0`; фоновая проверка также выполнялась во время работы API.
- Компанейская аналитика вернула 60 обращений, 90% с первым ответом, 60% с результатом, медиану 12 рабочих часов, 30 реализаций и 21 явное подтверждение. После фонового закрытия появилась отдельная ненулевая метрика подтверждения по умолчанию; явные подтверждения от этого не увеличились.

Временные обращения ручного сеанса удалены административным сбросом. Физический файл загрузки может остаться в storage согласно текущей политике хранения.

## Что имитируется и что не проверено

- Демо-вход позволяет намеренно выбрать любую демонстрационную личность; промышленного SSO нет. Это явно подписано в интерфейсе. JWT и проверки конкретного токена настоящие.
- AI остаётся детерминированным. Email и Битрикс24 не отправляются: `LogNotifier` пишет предполагаемую доставку в серверный лог.
- Анонимного конверта нет; nullable автор и флаг в модели — только задел, текущий API не позволяет включить анонимность.
- **Docker и PostgreSQL не запускались в среде агента.** Compose помечен как непроверенный. Проверены SQLite, миграции, сид и работающий API. Код ORM/агрегаций и миграция не используют SQLite-специфичные операции.
- **Полная повторная браузерная приёмка этого этапа не выполнялась**: браузерный инструмент недоступен. Проверены сборки и ручные операции через живой API; внешний вид и все пять сценариев по UI следует перепроверить оркестратору.
- `uvicorn --reload` в ограниченной Windows-среде упирается в `WinError 5` на named pipes. Проверен запуск без reload и короткая команда `uv run python -m app`. Это ограничение среды, а не подмена сервера моками.
- Для настоящего многопроцессного развёртывания нужен единственный выделенный планировщик или межпроцессная координация. Сейчас рассчитано на один API-процесс.
- Вложения пока без антивируса; незакреплённые файлы и физические файлы после сброса не очищаются автоматически. Локальные данные и секреты исключены из Git.
- Календарь не сокращает предпраздничный рабочий день. Доступные годы 2026–2027 задаются конфигом; его нужно обновлять для следующих лет.
- Mock не выполняет серверные SLA-задачи, не отправляет уведомления и не создаёт XLSX. Файлы mock доступны до перезагрузки. Это автономный UI-прототип, а не защищённый режим работы.

## Три новые изюминки, возможные благодаря серверу

1. **Квитанция целостности истории.** Добавить цепочку хешей событий и подписанную сервером квитанцию результата. Для компании из отрасли безопасности это даёт проверяемое подтверждение, что срок, ответственный и основание решения не переписаны задним числом. Сейчас есть обычный аудит; криптографическая проверяемость была бы отдельным развитием.
2. **Воспроизводимый отчёт «на дату».** Сохранять зафиксированный срез метрик и реестра для комиссии по улучшениям. Через месяц можно открыть именно тот состав и статусы, на основании которых принималось решение, даже после возвратов, новых участников и автоматических закрытий. Ценность — сопоставимые управленческие отчёты и объяснимость изменений KPI.
3. **Карантин и безопасный просмотр вложений.** Сервер проверяет файл антивирусом и формирует безопасную копию для просмотра; до окончания проверки документ не доступен другим пользователям. Это снижает риск распространения вредоносных офисных документов через внутренний канал и позволяет вести единые правила хранения материалов по обращениям.

Эти предложения не реализованы в этапе 2 и не повторяют ранее предложенные дайджест, анонимный конверт, опросы, паспорта передачи, проверку эффекта, карты рисков, подбор портфеля улучшений и совместную приёмку.
